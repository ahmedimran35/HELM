Scope confirmed: fix the canvas bug, restructure into a 3-pane editor, wire working drag-drop from a left palette, add a mini-map, wire per-node run indicators, snap-to-grid, and keyboard shortcuts. Inspector moves to the right via `SideSheet`; bottom drawer shrinks to a status bar. Code splits into a `workflow-editor/` folder.

### Critical fix (must do first)

`Canvas` div uses `flex-1` but its parent isn't a flex container; the div collapses to 0 height and `overflow-hidden` clips the SVG. Apply **Option B** from earlier analysis: change `className="flex-1 relative overflow-hidden bg-bg"` → `className="h-full relative overflow-hidden bg-bg"` in `Canvas.tsx`. (`canvasContainerRef` div in `Workflows.tsx` keeps `flex: 1 1 0%` from page flex column.) This single change makes the SVG paint; everything below is the redesign.

- Click on minimap background → pan center to that point.

### Keyboard shortcuts (one `useEffect` in `WorkflowEditorPage`)
| Key | Action |
|---|---|
| `Del` / `Backspace` (focus not in input) | delete selected node/edge (already partially in `deleteNode`/`deleteEdge`) |
| `Ctrl/Cmd+S` | call `save()` immediately |
| `Ctrl/Cmd+Z` | undo last graph change |
| `Ctrl/Cmd+D` | duplicate selected node (offset by +40,+40) |
| `Esc` | clear selection + close popup |
| `Space` (down) + drag | pan — implement by adding to Canvas's pan trigger |
| `F` | reset view, fit-to-nodes |
| `Ctrl/Cmd + wheel` | already in Canvas; nothing new |

The `useEffect` adds a `keydown` listener that respects focus: if `document.activeElement` is `INPUT`, `TEXTAREA`, or `[contenteditable]`, do nothing (so typing in the inspector doesn't delete the node).

### Risks / gotchas

1. **Mini-map math** is the trickiest piece. The map's coordinates are computed from `view`, `dims`, and `nodeBounds`. I'll keep the helpers in `helpers.ts` and add a small `MiniMap.test-helpers.ts` if needed.
2. **`Space+drag` pan** could clash with `Shift+drag` pan already in Canvas. I'll make Space the primary, keep Shift as a fallback.
3. **Undo stack** is in-memory only — if a user navigates away, undo is gone. That's intentional for v1; no backend migration.
4. **File split**: the `Workflows.tsx` re-exports nothing now. The router import path stays the same: `frontend/src/App.tsx` (or wherever) imports `WorkflowEditorPage` from the same module path. To make that work, `workflow-editor/index.tsx` re-exports the component and the new `Workflows.tsx` (still) re-exports it, so the router need not change.

Let me know if you want any of the small choices (mini-map size, snap default, undo stack depth, corner bracket style) adjusted before I start.
